# Private semantic owner fused validation experiment

The resolver-owned `semantic_job_fast::compile` is the same private single-file job as `semantic_job::compile`, except it calls `semantic_owner_fast::emit` and does not repeat `semantic_owner::verify` after that returns. The fused emitter validates the full expected source identity, source/lexical/type/proof Core and semantic effect/resource contract with `semantic_owner::valid`, checks the same declared depth/frame boundaries, then calls `short_emit::emit`. That emitter independently checks source and Core and calls the full source-bound `short_target::verify` decoder before returning bytes. Failure at any stage returns no Wasm; the three job failpoints remain before output publication.

For an accepted job, static call-chain inspection counts 15 direct `short_check::verify` invocations and four `short_target::verify` calls in the old job, versus six and one in this candidate. These totals describe this source revision and exclude other source/AST helper traversals. They are not physical-read counts, measurements, a full compiler comparison, or a guarantee of lower wall time. The candidate depends on `short_emit::emit` continuing to perform the full independent target check; any change to that contract requires re-review and regression tests.

The unchanged source identity, Core and bytes must be trusted job-owned immutable values across all checks and the single synchronous emission, with no concurrent mutation, callbacks, forged root handle, or copy/reset of owner state. The resolver's path, hardlink, file mutation, trusted package, capacity and host assumptions remain unchanged. Target decoding proves the produced bytes match the checked source/Core; it does not authenticate a filesystem revision or runtime reservation. Nothing permits untrusted callers to invoke an unchecked internal emitter or mutate after validation.

`semantic_owner_fast_test.goose` runs old and candidate emission over original and forged identity/source/Core fields, all target byte flips and truncations, cross-source/owner/target swaps and resource boundaries. `job_parity.py` builds both C-linked resolver jobs at O0/O2 and compares return status and output bytes on accepted U32, Bool, guard and loop programs, invalid effects/UTF-8, wrong name, traversal, depth failure and all failpoints. Both tests pass at O0 and O2. These tests do not establish equivalence under fault injection into allocators, asynchronous mutation, toolchain failure or full language input.

This pipeline is still unmetered except for a separate, unintegrated partial contract-meter prototype. Reducing required traversals changes logical C09 visits; current receipts cannot be reused as if counts were identical. No warm cache may use this optimization for admission until a complete versioned schedule accounts for the actual retained checks and ensures fresh/warm outcome equivalence. No public eligibility, runtime ABI, full C09, memory/fault qualification, or end-to-end speed claim follows.
