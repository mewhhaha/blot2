# Private scalar/loop semantic owner prototype

`semantic_owner::build` constructs a source-owned short scalar/finite-loop Core for one declaration, binds it to a caller-supplied package, module, declaration and exact source bytes, and requires the declaration to match the original source. `valid` independently rechecks that identity, the source-derived header, lexical bindings, types and existing range proofs, and a closed set of local scalar/loop operations. The stored empty effect set, declared depth/frame and inferred leaf depth/frame are all replayed; a stored summary is never evidence on its own.

`emit` accepts trusted invocation-local depth and frame inputs, checks the full declared contract with overflow-safe subtraction, uses the actual short emitter, then independently rechecks its complete source-bound Wasm target before returning owned bytes. Status 1 is invalid source/Core/target, 2 depth exhaustion or invalid depth capacity, and 3 frame exhaustion or invalid frame capacity. Failure returns no bytes. The target verifier independently enforces no calls or memory operations for this subset. The 1-depth, 0-frame inference concerns K1 managed callable depth and frame allocations only; Wasm locals, engine stack, runtime memory and host resource usage are outside this claim.

These identities are caller expectations, not proof of filesystem origin. A trusted resolver/job must supply stable correct package/module/declaration/source and nonconcurrently held snapshots. No content hash authenticates a maliciously substituted identity. Runtime capacity parameters are not authenticated, reserved, or restored by this prototype. This is one private consumer path over the existing short Core, not a general shared multi-module Core, effect-row solver, ownership checker, proof system, C09-metered pipeline, runtime ABI, or public K1 admission. It introduces repeated validation and hashing; no performance improvement is claimed.

The next generalization must give each module and declaration an owner scoped to the trusted resolver; lower all language constructs to one shared typed/effectful Core; model effect rows and resource composition across calls, loans and control flow; connect target lowering and target replay to that same Core; integrate runtime reserve/restore and deterministic failure; and charge every required source/IR visit under a versioned C09 policy. Independent checking must reject stale cross-job/cross-module IDs and mutated Core/target, rather than relying on source hashes or advisory inventories.
