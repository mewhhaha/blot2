# Fixed caller guard and data provenance checks

This private fixture checks one complete, source-gated, exactly pinned caller target. The inner checker decodes the machine call/descriptor sites and requires count guard and owner-slot guard to dominate the source-adapter call; it links the actual input/output descriptors through record, shim, project and worker operands. The outer checker additionally matches input-byte, offset, padding, input-copy, output-capacity and output-copy instruction shapes and checks their rejecting guards and loop exits dominate the relevant operation sites. Both independently callable APIs snapshot their input once using the built-in typed-array operations before any pin or decoder reads. Callers must not mutate bytes concurrently during that initial snapshot, and trusted JS/WebAssembly intrinsics are assumed.

Run the separately source-bound Goose `m12_helper_source_test.goose` first in the artifact directory, then run the four binding Node tests against that directory's `private-invoke.wasm`. O0/O2 controls reject every one-byte target mutation and every truncation; ten type-valid guard/descriptor mutations also fail the deliberately unpinned, test-only diagnostic. Subclass spoof, Proxy and detached-buffer controls cover the snapshot boundaries. That diagnostic does not admit execution or create capability authority.

The exact pin alone does not authenticate source, so the Goose source gate is mandatory. Runtime owner placement, initialized inputs, helper semantics, protected private memory and nonconcurrent invocation are separate assumptions. These checks are not a general Wasm analysis, a complete target-effects/frame proof, source-loan authority, M11, ABI/M12 qualification or a compiler performance claim. Neither integer descriptor fields nor a successful check grant runtime authority. Public eligibility remains false.
