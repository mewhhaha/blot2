## Outcome

Separate immutable Core module data from mutable building responsibilities and
reduce oversized state.

## Starting point

[core.zig](../zig-native/src/core.zig) defines `Module` and `Builder` alongside
dense node/side tables. Published Core must remain immutable while builders own
temporary construction state.

## Implementation checklist

- [ ] Move immutable module representation and mutable builder operations into
      distinct cohesive units.
- [ ] Keep IDs, spans, source ownership and freeze/clone/deinit behavior
      explicit at the boundary.
- [ ] Reduce oversized state rather than introducing forwarding-only
      abstractions; update direct users and imports.

## Validation

run `deno task test:compiler` and `deno task lint:zig` from the repository root
before the local milestone commit. Use the
[shared validation](README.md#shared-validation) commands for focused

- Run Core lowering, freezing, snapshot and allocation-failure tests plus full
  compiler/analyzer gates.
- Compare serialization, diagnostics, generated bytes and retained ownership
  before/after.
- Inspect public boundaries for leaked mutable buffers or solver IDs.

## Acceptance criteria

- [ ] Immutable module data and mutable construction have separate owners and
      clear APIs.
- [ ] No behavior, ownership or representation change is hidden in the refactor.
- [ ] Applicable checks pass and completion evidence records remaining
