# Private resolver-backed leaf and call-chain job

The job builds one source graph from the live trusted root and checks every path, import span, alias and normalized target against the same owned graph. A single-module graph uses the checked semantic owner with exact declaration and source; a multi-module graph uses the existing independent `chain_program` source, interface and direct-call verifier and the independently decoded target. It rejects cyclic imports, ambiguous/shadowed aliases, unresolved or invisible names, wrong declaration, insufficient declared chain depth and nonzero required frame in the bounded chain subset. A successful multi-entry target exports every checked root entry, with the requested name required to exist. Its opaque 32-byte ABI input is a trusted fixture expectation, not an authenticated manifest or a qualified public ABI. The single-module branch checks the byte length only; it does not use or authenticate the ABI value.

All checks consume one owned graph snapshot: no untrusted caller graph, external source digest or caller-supplied capability is admitted. Root descriptor and its package mapping, entry selection, ABI bytes and capacities are trusted. Capacity checks are compile-time comparisons against checked declared fixture bounds, not runtime reservation, engine stack qualification or full M11. Source is read sequentially from a mutable filesystem, so concurrent in-place changes may give a torn file or mixed graph; stable files and exclusive root lifetime are prerequisites. Root path containment is delegated to the existing Linux openat2 resolver and trusted policy for hardlinks/special files. Actual resolver failure publication, host OOM and output I/O atomicity are not qualified. Explicit failpoints cover only three synchronous stages.

The supported graph shape is intentionally narrow: one public scalar leaf or direct-call declaration per non-root module, root private one-line call entries, U32-only, no general semantic_owner program inside imported leaf modules, no general overload/visibility/monomorphization, dependency observation completeness, incremental cache, source authority proof, C09 or public compiler integration. The same job type has two target formats: a single module uses the private scalar/loop target, a chain uses the private chain target; neither target is a certified K1 public artifact. The C+Goose+Node `semantic_graph_job_test.py` builds both O0/O2, checks leaf and multi-module execution and changed-source behavior, path escapes/missing sources, cycles, duplicate/shadowed aliases, wrong exports, malformed resource depth and no-output injected failures. Existing project/chain independent graph mutation and byte-forgery tests remain separate prerequisites.
