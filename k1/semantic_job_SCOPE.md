# Private resolver-bound semantic job

This private single-module job takes a trusted live non-copied root descriptor, an opaque trusted package identity fixed in that root, a requested logical module path and declaration, and caller-supplied capacity. It resolves one file under the root with the existing descriptor-relative resolver, retaining the exact resolver-owned bytes. The same byte snapshot, root package, module and declaration feed source-identity replay, semantic-owner source checks, target generation and target revalidation; staged failure paths return no bytes. No external digest or claimed source record is accepted. The request and root-to-package mapping remain trusted inputs: this does not decide which package or declaration ought to be compiled, issue bearer authority, or validate a project import graph.

Root handles and package mapping must not be copied, closed or mutated concurrently; the filesystem is not a coherent atomic snapshot and in-place writes during reading can produce a mixed source snapshot. The resolver provides descriptor-root containment under supported Linux openat2 semantics and fails closed on unsupported kernels/platforms. The trusted root policy must address hardlinks and special files; pathname containment alone does not authenticate file content. Linux/host filesystem integrity, immutable source during each semantic check, OOM, host process/engine faults, and asynchronous cancellation are assumptions. Failure injection only covers three explicit staging points, not arbitrary host failure. No K1 public ABI, M11, runtime reservation, C09, engine stack, general import graph or cache qualification follows.

`GOOSE=/tmp/k1-goose/build/goose GOOSE_HOME=/tmp/k1-goose-home python3 /workspace/.issue37-goose/k1/semantic_job_test.py` builds actual Goose+C fixture at O0 and O2. It checks changed and restored source and resulting Wasm execution, guarded constant-offset boundary execution against the shared checker, same-root symlink, denied outside links and path traversal, missing/bad-UTF8/empty source, wrong declaration, insufficient depth and injected read/check/emission-stage failure with no stdout. Package IDs are opaque trusted identifiers, not filesystem paths; the empty identity is rejected. Other lower-level resolver race and fault suites remain separate prerequisites.
