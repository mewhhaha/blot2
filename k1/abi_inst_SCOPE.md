# Source-derived tuple instantiation with actual generic call

This private experiment accepts one exact two-declaration module: the existing source-checked generic identity function and a fixed `apply` function whose argument type, result type, and explicit `identity@[T]` substitution are the same source spelling of a 2–16-field U32 tuple. It derives the tuple directly from the complete module bytes. The producer uses the lexer-based tuple recognizer and the source verifier reconstructs the whole canonical module with the separately implemented tuple byte parser; extra declarations, shadowing, mismatched argument/result/substitution, malformed fields, and all other forms fail closed. Semantically equivalent whitespace differences among the three spellings are conservatively unsupported.

The emitter uses the source-derived checked tuple/dictionary integration to create an actual two-function Wasm module. Its concrete caller uses an aggregate argument/result slot and directly calls the generic identity body with a 16-byte dictionary in a data segment. A separate fixed-target decoder verifies every emitted byte, function index, call sequence, and dictionary field against the source-derived tuple width. Node executes all widths 2–16 and checks copied bytes and adjacent sentinels. The test mutates every source and target byte, truncates each target and exercises explicit substitution mismatches at O0/O2.

This is a strict fixture, not a general parser, type checker, instantiation engine, layout/overload registry, public ABI, complete M10, M11 resource proof, M13 certificate or C09 accounting. It accepts a tiny hard-coded generic body and one caller rather than arbitrary source; the generated private target exports raw memory, and the runtime dictionary must remain protected from host mutation. Initialized input, exclusive disjoint output slots, logical moves and loan authority are trusted execution preconditions. The K1 source/header resource declarations are re-recognized but not generally qualified. Public eligibility is always false.
