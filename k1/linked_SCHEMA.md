# Private linked scalar compilation fixture

This experimental path compiles one source-owned entry module calling one selected public provider through an import. It supports only the checked U32 scalar subset (identity, constants, and bitwise AND). The provider must declare depth below 128 and frame zero; this is a conservative fixture restriction, not a complete resource or host-engine qualification. The ABI identity is the caller-supplied 32-byte identity, not evidence of a qualified K1 ABI. This is not a complete K1 frontend, project compiler, generic ABI, or C09 implementation.

The compiler reads a bounded source graph through a trusted live root descriptor, resolves the source-backed import and interface, and independently revalidates the source-derived plan before emission. The generated WebAssembly has two functions, fixed 275-page memory, no imports, and a direct call from the exported entry to the provider. An independent checker verifies the complete module and associates the instructions with the checked source and plan. Verification of a supplied in-memory graph and target does not authenticate their filesystem origin. The root descriptor must remain live and must not be copied or concurrently closed. Reads occur separately against a mutable filesystem, so they do not provide a coherent filesystem snapshot. Unsupported resolver platforms fail closed.

A sequential session owns bounded retained revisions. Each update rereads sources, rechecks dependencies, recompiles, and revalidates the result; it does not skip compilation. A provider body change can preserve the semantic interface while requiring a different target. Failed updates preserve the preceding successful generation; missing lookup observations are available on the failure result, and optional probes are caller-scoped. The `current` operation revalidates the internally held plan and bytes but returns a historical revision, not a statement about the present filesystem. After the eight-version retention limit, a successful update returns fresh bytes without retaining another version.

Publication is staged for the checked, synchronous failure paths covered by the tests. It does not claim atomicity under recoverable out-of-memory failures, asynchronous cancellation, or concurrent access; nor does it authenticate disk artifacts. The session and its root are trusted, compiler-owned state.
